## 📖 Описание проекта

**«Справочник: Полиция»** — настольное объектно-ориентированное приложение на C++ и Qt 6, предназначенное для автоматизации учёта и обработки информации правоохранительных органов.

Система решает задачу учёта двух взаимосвязанных предметных сущностей:
1. **Справочник «Заявления»** — содержит зарегистрированные заявления граждан (номер заявления, ФИО заявителя, фабула/описание происшествия).
2. **Справочник «Следствия»** — содержит сведения о следственных действиях, прикреплённых к заявлениям (номер заявления, ФИО следователя, статус дела, дата возбуждения).

Система гарантирует реляционную целостность данных: следствие не может существовать без соответствующего заявления, а при удалении заявления выполняется каскадное удаление всех ассоциированных с ним следствий (с подтверждением пользователя).

## ⚡ Функциональные возможности

- 📂 **Импорт / Экспорт данных**: чтение и запись справочников в текстовые файлы стандарта LFN (`.txt`) с валидацией строк на корректность.
- ➕ **Добавление записей**: строгий контроль корректности форматов (русские символы, правила капитализации, формат даты `<ДД МММ ГГГГ>`, календарные ограничения с учётом високосных лет).
- ❌ **Удаление записей**:
  - Быстрое удаление за счёт перемещения последнего элемента на место удалённого (swap with back) за $O(1)$ в массиве с синхронным обновлением индексов.
  - Каскадное удаление зависимых следствий при удалении заявления.
- 🔍 **Мгновенный поиск**:
  - Поиск заявления по уникальному номеру — в среднем за $O(1)$ (через хеш-таблицу).
  - Поиск следствий по номеру заявления — за $O(\log N)$ (через RB-дерево).
  - Отображение точного количества шагов поиска для оценки сложности.
- 📊 **Формирование сводного отчёта**: фильтрация и объединение записей двух справочников по критериям: *ФИО заявителя*, *статус следствия*, *дата возбуждения* (использует комбинированный поиск через RB-дерево по датам и хеш-таблицу).
- 🛠 **Окна отладки и визуализации структур данных**:
  - Просмотр реального состояния статических массивов.
  - Просмотр ячеек хеш-таблицы (индекс, ключ, значение, первичный хеш, коллизии/число шагов).
  - Просмотр красно-чёрных деревьев с раскраской узлов (`R`/`B`) и динамическими списками индексов.
- ⚙️ **Динамическое изменение вместимости хеш-таблицы**: ручной рехешинг с контролем коэффициента заполненности ($0.25 < \alpha < 0.75$).

## 🏗 Архитектура и паттерны проектирования

В реализации архитектуры проекта были использованы некоторые паттерны ООП:

1. **Facade (Фасад)**:
   - `DataManagerHashTable` —  реализует логику совместной работы массива заявлений `StaticArray<PoliceReport>` и динамической хеш-таблицы `HashTable<unsigned int, unsigned int>`.
   - `DataManagerTree` — реализует логику работы хранилища `StaticArray<Investigation>` с двумя красно-чёрными деревьями (`RB_tree<unsigned int, unsigned int>` по номерам и `RB_tree<Date, unsigned int>` по датам).
2. **Iterator (Итератор)**:
   - Вложенный класс `ForwardIterator` в `List<T>`, обеспечивающий безопасный однонаправленный обход элементов кольцевого двусвязного списка без нарушения принципов инкапсуляции.
3. **Singleton (Одиночка)**:
   - Класс `DataDataService` – реализован для синхронизации взаимодействия справочников и взаимодействия UI с бэкендом программы `DataDataService`.
   - Предоставляет доступ к высокоуровневым методам для взаимодействия с системой.

## 🧠 Алгоритмы и структуры данных

Все ключевые структуры данных реализованы **вручную (from scratch)** оприаясь на лицензированную литературу:

### 1. Динамическая хеш-таблица с открытой адресацией
- **Назначение**: Хранит пары(ключ-значение) `(Номер заявления → Индекс в массиве заявлений)`.
- **Хеш-функция**: мультипликативная хеш-функция на основе золотого сечения ($A \approx 0.618033$):
  $$h(k) = \lfloor m \cdot (k \cdot A \bmod 1) \rfloor$$
  где строка/число конвертируется побайтово в UTF-8 сумму кодов.
- **Разрешение коллизий**: метод линейного пробирования с шагом 1:
  $$h_2(p, i) = (p + i) \bmod m$$
- **Контроль фактора загрузки (Load Factor)**:
  - Автоматическое расширение (expand) в 2 раза при достижении коэффициента $\alpha \ge 0.75$.
  - Автоматическое сжатие (reduce) в 2 раза при падении $\alpha \le 0.25$ (минимальная вместимость 4).
  - Алгоритм удаления с повторной перевставкой элементов кластера для предотвращения разрыва цепочек поиска.

### 2. Красно-чёрное дерево (Red-Black Tree)
- **Назначение**:
  - `tree` — индекс следствий по ключу `Номер заявления`.
  - `tree_dates` — индекс следствий по ключу `Дата возбуждения`.
- **Свойства**: бинарное дерево поиска со строгим соблюдением 5 свойств RB-дерева. Гарантирует поиск, вставку и удаление за $O(\log N)$.
- **Балансировка**: реализация малых и больших левых/правых поворотов, перекраски узлов при вставке (4 случая) и удалении чёрных вершин (4 случая).
- **Значение узла**: указатель на пользовательский кольцевой двусвязный список индексов, что позволяет хранить несколько следствий для одного заявления / даты.

### 3. Кольцевой двусвязный упорядоченный список
- **Назначение**: хранение множественных индексов в узлах красно-чёрного дерева.
- **Особенности**: элементы поддерживаются строго отсортированными по возрастанию благодаря методу вставки – (`ascend_add`).

### 4. Статический массив
- **Класс**: `StaticArray<Info>` емкостью 9999 элементов.
- **Особенности**: доступ по индексу за $O(1)$. Удаление элемента внутри массива производится за $O(1)$ методом перемещения последнего элемента на место удаляемого с последующим обновлением связей в индексных структурах.

## 🔗 Связи между сущностями и формирование отчёта

```
 [ Справочник Заявлений ]                         [ Справочник Следствий ]
  StaticArray<PoliceReport>                       StaticArray<Investigation>
             ▲                                                ▲
             │ (индекс)                                       │ (индексы)
┌────────────────────────────┐                  ┌────────────────────────────┐
│      HashTable             │                  │       RB_tree (КЧД)        │
│   Key: Номер заявления     │  ◄── 1 : N ──►   │    Key: Номер заявления    │
│   Val: Индекс в массиве    │                  │  Val: List<Индексов в мас> │
└────────────────────────────┘                  └────────────────────────────┘
                                                              ▲
                                                ┌────────────────────────────┐
                                                │     RB_tree_dates (КЧД)    │
                                                │    Key: Дата возбуждения   │
                                                │  Val: List<Индексов в мас> │
                                                └────────────────────────────┘
```

**Алгоритм формирования отчёта «Следствия по заявлениям»**:
1. По дереву `tree_dates` за $O(\log N)$ находится список следствий на заданную дату.
2. Для каждого следствия проверяется совпадение фильтра по статусу.
3. По номеру заявления через хеш-таблицу за $O(1)$ извлекается соответствующее заявление.
4. Проверяется совпадение по ФИО заявителя.
5. При совпадении формируется строка отчёта.

## 📄 Форматы входных и выходных данных

### Заявления (`reports.txt`)
Первая строка — количество записей $N$, далее строки формата:  
`<Номер_заявления> <Фамилия> <Имя> <Отчество> <Описание>`

### Следствия (`investigations.txt`)
Первая строка — количество записей $M$, далее строки формата:  
`<Номер_заявления> <Фамилия> <Имя> <Отчество> <Статус> <ДД МММ ГГГГ>`

Интерфейс построен на базе **Qt Widgets / Qt Designer**:
- **Два синхронизированных главных окна**: главное окно заявлений и окно следствий.

- **Панель инструментов (Toolbar)**:
  - 📥 Загрузка справочника из файла
  - 💾 Сохранение справочника в файл
  - 📋 Формирование отчёта
  - 🔍 Поиск по номеру с отображением числа шагов
  - ➕ Добавление новой записи через диалоговое окно
  - ❌ Удаление выделенной записи
  - 🖨 Просмотр внутренних структур данных
  - ⚙️ Изменение вместимости хеш-таблицы

## 🚀 Сборка и запуск

### Требования
- Компилятор с поддержкой **C++17** (MSVC 2019/2022, GCC 9+, Clang 11+)
- **Qt 6.11.1** (или совместимая версия Qt 6.x)
- **CMake** (3.16+) или **qmake**

### Сборка через Qt Creator
1. Откройте файл проекта (`CMakeLists.txt` или `.pro`) в **Qt Creator**.
2. Выберите установленный комплект (Kit) с версией **Qt 6.11.1**.
3. Нажмите кнопку **Собрать** (Ctrl+B) и затем **Запустить** (Ctrl+R).
